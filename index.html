01 — About

Hands-on, security-first, and comfortable in the logs.

I am a systems and security engineer focused on building, hardening, and operating resilient Linux infrastructure. My work is self-directed and lab-based: I research, deploy, and troubleshoot enterprise-grade technologies under real constraints — segmented networks, centralized logging, zero-trust access, and full lifecycle ownership from first boot to recovery.

I care about the parts of the job that are hard to fake: proving a SIEM actually detects an adversary, recovering a corrupted cluster, and making an endpoint patchable again when the package manager is broken.

Disciplined persistence

Rigorous habits around log analysis, syntax validation, and command-line diagnostics.

03 — Approach

How I work

Good infrastructure work is mostly about managing limited resources well — including an AI assistant's context window.

Treat context as a budget

In long AI-assisted sessions I scope work into small tasks, compact or summarize before the context window saturates, and keep a rolling log of decisions so detail survives summarization.

Always have a fallback

When a model or provider throttles, I switch to an equivalent model instead of blocking, and keep a local option for offline work. No single dependency should stall the job.

Verify, then execute

I read, sanity-check, and test AI-suggested commands in a disposable environment before they touch a real host. Suggestions are inputs, not instructions.

Write the recovery path

Every dependency gets a fallback and a documented procedure, so a single failure is an inconvenience instead of a crisis. Rebuildability is a security property.
